## File naming

Indonesian (the default) lives in the **base file with no suffix**; every other
language is a sibling with a suffix inserted before `.md`:

```text
1.3-Orkestrasi-Dasar/
├── Ch1-Keluarga-Instrumen-Ranges.md      ← Indonesian (base, primary)
├── Ch1-Keluarga-Instrumen-Ranges.en.md   ← English
├── Ch1-Keluarga-Instrumen-Ranges.zh.md   ← Chinese
├── Ch1-Keluarga-Instrumen-Ranges.it.md   ← Italian
├── Ch1-Keluarga-Instrumen-Ranges.fr.md   ← French
├── Ch1-Keluarga-Instrumen-Ranges.de.md   ← German
├── Ch1-Keluarga-Instrumen-Ranges.nl.md   ← Dutch
├── Ch1-Keluarga-Instrumen-Ranges.es.md   ← Spanish
└── Ch1-Keluarga-Instrumen-Ranges.ja.md   ← Japanese
```

Root docs follow the same rule: `README.md` / `README.en.md`, `guide.md` /
`guide.en.md`, `sillaby.md` / `sillaby.en.md`, `toc.md` / `toc.en.md`.

## Resolution & fallback

1. Request language `L` for document `base.md` → try `base.{L}.md`.
2. If missing → fall back to `base.md` (Indonesian).
3. The webview shows a badge when a fallback is active.

The sidebar tree always lists **base files only**; the language switcher
re-resolves the current document client-side.

## Translation rules

- Translate **prose**: headings, paragraphs, lists, tables, blockquotes.
- **Keep unchanged**: YAML frontmatter keys; `xml_tags` and `software` values;
  file names and cross-links; XML/JSON/code inside fences (translate XML
  *comments'* wording only); URLs; book titles in their original language
  (English gloss may be added in parentheses).
- Translate `title:` in frontmatter to the target language. `tier:` / `subject:`
  prose values should be translated; folder-derived identifiers stay as-is.
- Use standard **English/Target-language music-theory terminology** (voice
  leading, transposition, counterpoint…). Keep universally used Italian terms
  (*adagio*, *pizzicato*) as loanwords per target-language convention.
- Preserve heading hierarchy, emoji, table structure, and the `Level 5`
  section naming.
- Full translations only — never summarize or omit sections.

## Status tracking

Update `status` in `i18n.json` when a language stage completes:
`pending` → `in progress` → `complete`.
